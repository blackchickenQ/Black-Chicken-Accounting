# 乌鸡记账适配鸿蒙7（HarmonyOS 26.0.0）实施方案

## Goal

1. 工程升级：`targetSdkVersion: '6.1.1(24)'` → `'26.0.0'`（鸿蒙7，本机 SDK 已是 26.0.0 Release），`compatibleSdkVersion` 保持 `'5.0.2(14)'` 以覆盖老设备。
2. 新特性适配：沉浸光感/材质效果（鸿蒙7旗舰 UI 特性，要求 targetSDK ≥ 26.0.0）、通知设置半模态拉起；所有 26.0.0 专属 API 用 `apiAvailable()/canIUse` 守卫，低版本回退。
3. 全面重构：废弃 API 清理（promptAction 等）、router→Navigation、V1→V2 状态管理。

## Scope / Non-goals

**包含**：上述三部分；版本号升级（versionName 1.5.0 → 2.0.0，versionCode 1000007 → 1000008，可调整）。

**不包含**：V1 状态管理以外的数据层重构（Preferences 持久化保持现状）；RDB 迁移；无障碍/国际化增强；`HdsTabs`（@kit.UIDesignKit）替换（仅验证可用性）；GuideIntroPage 之外的启动流程改造；性能专项（LazyForEach 等）。

## Current State And Constraints

- 33 个 .ets 文件：17 个 @Entry 页面 + 11 个 common/ 模块 + entryability/entryformability/entrybackupability + 2 个桌面卡片页面。
- 状态管理：V1 为主（@State/@Prop/@StorageProp/AppStorage），唯一 V2 组件 `SearchBillSheetContent`（Index.ets:1244-1249）。全局 AppStorage 信号：`isWideScreen`、`statusBarVp`、`navBarVp`、品牌色。
- 导航：全部 `router`（约 20 处 pushUrl，EntryAbility.ets:177 隐私重锁也用 router.back）；主页面为 `HdsTabs` 5 Tab 结构，Index.ets 共 11,269 行（高风险文件）。
- 废弃 API：`promptAction.showToast/showDialog` 全局调用 100+ 处（API 15 起废弃）；`getContext(this)` 1 处（Index.ets:6761）；死导入 `uiAppearance`（Index.ets:19）。
- **shadow 行为变更风险**：45+ 处 `.shadow({ radius: 0, ... })` 水墨风硬阴影；26.0.0 起 ShadowOptions.radius 行为有变（此前 radius=0 不绘制阴影），需读文档《开发指南/ArkUI/.../阴影/arkts-shadow-effect》确认并视觉回归。
- 持久化：仅 Preferences（'bill_data'，JSON 序列化），无 RDB/原生代码/Web 组件；Canvas 图表 3 处（Index.ets:8808/8894/8959）。
- 通知/提醒：`notificationManager.requestEnableNotification`（Index.ets:6567）+ `reminderAgentManager.publishReminder` 周记账提醒（Index.ets:6617-6642），受 `CLOUD_FEATURES_ENABLED` 开关控制；权限 `ohos.permission.PUBLISH_AGENT_REMINDER` 已声明。
- 三方依赖需在 SDK 26 下重验：`@archermind/exceljs`、`cjcalendar`、`@mlethe/calendar`、本地 HAR `base_calendar`/`base_apis`。
- 版本号语义：26.0.0 > 6.1.1(24)；`devecocli check compat` 工具对 6.1.1(24)→26.0.0 存在版本字符串比较 bug（判定 26 < 6.1.1），**不可用**，兼容性以编译 + codelinter 兜底。
- 点分版本号：7.0 起 API 兼容判断用 `apiAvailable()`（见 FAQ《点分版本号变更后API兼容性判断方式说明》faq-basics-service-kit-19）。
- **无需新增权限**（沉浸光感、通知半模态均不需要新 ohos.permission）。
- 工作区当前有大量未提交改动（v1.5.0 功能迭代，含未跟踪文件），必须先做 Phase 0。

## Design

### Phase 0：安全基线
1. 将当前工作区全部改动（含未跟踪的 PlaygroundPage/GameplayPlus/图标资源等）提交到新分支 `feature/harmony7-adaptation`（从当前 HEAD 切出），提交信息如 `chore: v1.5.0 基线快照（鸿蒙7适配前）`。
2. 后续每个 Phase 完成且通过验证门后各做一次 git 提交，支持逐阶段回退。

### Phase 1：SDK 升级（配置 + 编译修复）
1. [build-profile.json5](build-profile.json5)：products[0].targetSdkVersion `'6.1.1(24)'` → `'26.0.0'`；compatibleSdkVersion 保持 `'5.0.2(14)'`；versionCode 1000007 → 1000008（与 app.json5 同步）。
2. [AppScope/app.json5](AppScope/app.json5)：versionName `'1.5.0'` → `'2.0.0'`，versionCode 1000007 → 1000008。
3. [oh-package.json5](oh-package.json5)：modelVersion `'6.1.1'` → `'26.0.0'`（若 hvigor 报不兼容再按提示调整）。
4. `ohpm install` 重新解析依赖；确认 `@archermind/exceljs`、`cjcalendar`、`@mlethe/calendar`、本地 HAR 在 SDK 26 下可编译。
5. 验证 `HdsTabs`/`@kit.UIDesignKit`（Index.ets:11,8225）在 SDK 26 下可用；**若不可用**，回退方案：替换为标准 `Tabs`+自定义 tab bar（保持 5 Tab 结构与宽屏 BarPosition 逻辑），此为独立子任务。
6. `devecocli build` 修复全部编译错误/警告（重点：SDK 26 下 d.ts 变化导致的类型不匹配）。

### Phase 2：废弃 API 清理
1. **promptAction 迁移（100+ 处，机械替换）**：`promptAction.showToast(...)` → `this.getUIContext().getPromptAction().showToast(...)`；`await promptAction.showDialog(...)` 同理（返回 Promise 语义不变）。涉及全部 17 个页面文件。注意：仅在自定义组件方法内替换（当前所有调用点均满足）；替换后删除各文件顶部 `promptAction` 导入（保留其他 @kit.ArkUI 导入）。
2. `getContext(this)`（Index.ets:6761）→ `this.getUIContext().getHostContext()`（Index.ets:6605 已有该模式可参照）。
3. 删除死导入 `uiAppearance`（Index.ets:19）。
4. **shadow 行为变更**：读文档 `devecocli docs read "开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/使用动画/动画效果/阴影/arkts-shadow-effect"` 确认 26.0.0 的 radius 新行为；45+ 处 `radius: 0` 水墨阴影若视觉回归异常，统一调整（预案：改为极小 radius 如 0.1，或按文档推荐写法）。
5. `PhotoViewPicker`（common/BillPhotos.ets:46-50）：查 26.0.0 废弃状态；若已明确废弃则迁移到新 picker API 并用 `canIUse` 守卫，否则保留（低优先级，允许延后）。

### Phase 3：鸿蒙7新特性（全部带低版本守卫）
1. **沉浸光感/材质效果**（26.0.0 旗舰特性，要求 targetSDK ≥ 26.0.0，Phase 1 后满足）：
   - 读文档 `arkts-immersive-light-sense-enable`（开发指南/ArkUI/沉浸光感/开启沉浸光感）及功耗优化篇。
   - 应用级开启 + 组件级材质应用于：Index 主页面背景/Tab 栏、主要半模态 sheet（AddBillSheetContent 等）。
   - 兼容 5.0.2(14)：按 faq-basics-service-kit-19 用 `apiAvailable('26.0.0')`（或 `canIUse`）守卫，低版本走现有纯色背景路径。
2. **通知设置半模态**：26.0.0 Notification Kit 支持半模态拉起应用通知设置界面；改造 Index.ets:6567 `requestEnableNotification` 流程——26.0.0 设备上被拒/未开启时用新 API 半模态引导，低版本回退现状。API 名以 Notification Kit 26.0.0 新增接口文档为准。
3. **（可选，时间允许）** reminderAgentManager 26.0.0 新增时区类型提醒：为周期记账提醒增加按用户时区重复计算的能力（Index.ets:6617-6642），apiAvailable 守卫。
4. 每项特性独立提交，便于单独回退。

### Phase 4：router → Navigation 重构
1. Index.ets 主页面引入 `Navigation(this.pathStack)`（`NavPathStack`，mode 保持 Stack；`HdsTabs` 及 5 个 TabContent 结构不变，包在 Navigation 内）。
2. 16 个子页面从 `@Entry` 改为 `NavDestination` 组件（去掉 @Entry，build 根节点包 NavDestination，`.onBackPressed` 处理返回语义）；通过 pageMap（navDestination builder）注册路由表。
3. 路由调用替换：`router.pushUrl({ url: 'pages/XxxPage', params })` → `this.pathStack.pushPathByName('XxxPage', params)`；`router.back()` → `pathStack.pop()`；`router.getParams()` → `NavPathStack` 参数获取（CategoryManagePage.ets:28 等接收端同步改）。
4. EntryAbility 隐私重锁（EntryAbility.ets:165-190 的 router 用法）：改为 AppStorage 信号（如 `privacy_relock_request`）由 Index 监听后清空 pathStack 回首页。
5. [main_pages.json](entry/src/main/resources/base/profile/main_pages.json) 只保留 `pages/Index`（GuideIntroPage 可保留为独立启动页或改为首个 destination，二选一，推荐后者以统一导航栈；EntryAbility 首启判断逻辑对应调整）。
6. 桌面卡片（EntryFormAbility）不受影响（不使用 router）；wantAgent 回跳 EntryAbility 逻辑不变。

### Phase 5：V1 → V2 状态管理迁移（分批）
1. 装饰器映射：`@State`→`@Local`；`@Prop`→`@Param`（一次性传入加 `@Once`）；`@Watch`→`@Monitor`；`@Provide/@Consume`→`@ProviderV2/@ConsumerV2`（当前未用）；`AppStorage`/`@StorageProp` 写读两端 → `AppStorageV2`；struct 加 `@ComponentV2`（@Entry 兼容 @ComponentV2）。
2. **全局信号迁移先行**：`isWideScreen`、`statusBarVp`、`navBarVp`、品牌色（EntryAbility 写入 + 各页 @StorageProp 读取）统一迁移到 `AppStorageV2`（注意 AppStorageV2 需通过 `AppStorageV2.connect(type, key)` 访问，定义一个共享 class 包装），这是所有页面迁移的前置。
3. 迁移顺序（自底向上、风险递增）：
   - 批次A：common/ 中含装饰器的组件（Motion.ets 的 BounceTouch、HandIcon.ets）；
   - 批次B：简单页面（TagManagePage、CategoryManagePage、RecycleBinPage 等）；
   - 批次C：复杂页面（WealthTab、CalendarTab、PlaygroundPage、报告类页面）；
   - 批次D：Index.ets 的 ~15 个子组件 struct（AddBillSheetContent、EditBillSheetContent、PinSetup/PinVerifyDialog 等）；
   - 批次E：Index.ets 主 struct（@Entry）最后迁移。
4. 每批迁移后跑 `arkts_check` + `devecocli build`；V1/V2 混用规则：@ComponentV2 内禁止 V1 装饰器，但可包含未迁移的 V1 子组件（保证渐进可行）；`@LocalStorageProp`（widget 卡片）**不迁移**（卡片页保持现状）。
5. 已有 V2 组件 SearchBillSheetContent（Index.ets:1244）作为样板参照。

### 验证门（每 Phase 结束）
- `arkts_check`（变更的 .ets 文件）→ `devecocli build` 通过 → git 提交。

## Execution Sequence

1. Phase 0 → 验证：`git status` 干净、分支正确。
2. Phase 1 → 验证门（build 通过，HdsTabs 可用性结论明确）。
3. Phase 2 → 验证门 + shadow/深浅色视觉抽查。
4. Phase 3 → 验证门 + 新特性在 API 26 模拟器上人工确认 + 低版本回退路径确认（代码审查 apiAvailable 守卫完整性）。
5. Phase 4 → 验证门 + 全部页面跳转/返回/参数传递人工回归 + 隐私重锁场景验证。
6. Phase 5 → 每批次验证门；批次E 完成后全功能回归。
7. Phase 6 最终验证（见下）。

## Verification

| 项 | 方法 |
|---|---|

## Risks And Compatibility

| 风险 | 影响 | 缓解 |
|---|---|---|
| shadow radius=0 行为变更（45+ 处水墨风） | 视觉回归 | Phase 2 专项确认文档+模拟器对比，统一预案调整 |
| HdsTabs/@kit.UIDesignKit 在 SDK 26 不可用/行为变化 | 主页面结构 | Phase 1 验证；回退标准 Tabs 方案（独立子任务） |
| 三方库（exceljs/cjcalendar/@mlethe/calendar）SDK 26 编译失败 | 导入导出/日历功能 | 锁定可用版本或寻找替代库；最坏情况该功能临时下线（exceljs 走 taskpool 已隔离） |
| Index.ets 11k 行上的多轮大规模改动 | 合并冲突/引入回归 | 严格分 Phase 提交；每 Phase 验证门；禁止无关代码重排 |
| AppStorage→AppStorageV2 全局信号迁移 | 所有页面的响应式失效风险 | Phase 5 批次先行迁移并单独验证；保持 key 语义一致 |
| 提醒配额/AGC 授权模型在 26 变化 | 周记账提醒 | 已有 CLOUD_FEATURES_ENABLED 开关兜底；模拟器实测 |
| compatibleSdkVersion 5.0.2(14) + target 26.0.0 组合 | 老设备运行 | 全部新 API 守卫；上架前在多档位设备/模拟器抽查 |
| 兼容扫描工具 bug | 漏检 API 变更 | build + codelinter 兜底；发布前人工 diff SDK d.ts 关键模块 |

## Rollback

- **逐阶段回退**：每 Phase 独立 git 提交（分支 `feature/harmony7-adaptation`），任一阶段失败 `git revert`/`git reset` 到上一阶段提交。
- **整体回退**：回到 Phase 0 基线提交（v1.5.0 快照）；配置层还原 build-profile.json5（targetSdkVersion `'6.1.1(24)'`）、oh-package.json5（modelVersion `'6.1.1'`）、app.json5（1.5.0/1000007）后按原配置重新 `ohpm install` + build。
- 新特性（Phase 3）每项独立提交且均有低版本回退路径，可单独摘除不影响主线。
